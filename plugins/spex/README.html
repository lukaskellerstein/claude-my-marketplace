spex next <dir> reads the files and prints the one command, whether to /clear first, and whether auto mode is on. A refusal prints a code and a fix: the fix is the answer. A blocked task names its reason file, and /spex:develop <dir> <task> unblocks it.
Also: /spex:init once per repo · /spex:update after a plugin update, it moves old proof lines into tests.yaml · /spex:clarify and /spex:research are the way back in for a question or an unknown that opens later · /spex:ship <dir> --merged after a merge you made yourself.
